1. Homepage + catalog photos

Browser → gateway :8090 → admin-bff :8083 → (optional) scrape store websites → images on disk

Path

  1. Open / (HomeComponent)
  2. GET /api/catalog/deals and GET /api/catalog/stores
  3. If images missing → POST /api/catalog/scrape (background)
  4. Images served as GET /api/catalog/images/deal/{id}

# Force scrape (takes a few minutes)
Invoke-RestMethod http://localhost:8090/api/catalog/scrape -Method POST

# Open a deal image in browser (use an id that has scrapeStatus OK)

2. Customer submits order (search term)

UI /orders/new → gateway → intake → HTTP create on order → after commit → Kafka oms.orders.created → delivery (status Created) + allocation (ceilings)

Path

  1. POST /api/orders { customerId, lines: [{ searchTerm, quantity }] }
  2. Intake validates → calls order-service POST /api/internal/orders
  3. Order saved in shared oms DB (H2 file or Postgres)
  4. After commit, publishes to Kafka → delivery & allocation listeners

Files

web-app/src/app/pages/customer-order/customer-order.component.ts web-app/src/app/core/api.service.ts (submitOrder) api-gateway/.../application.yml (Path=/api/orders → intake) intake-service/.../api/IntakeController.java intake-service/.../service/IntakeApplicationService.java order-service/.../api/OrderController.java order-service/.../service/OrderApplicationService.java oms-eventing/.../Topics.java oms-eventing/.../publish/DomainEventPublisher.java (after-commit Kafka publish) delivery-service/.../DeliveryApplicationService.java (@KafkaListener ORDERS_CREATED) allocation-service/.../messaging/OrderCreatedListener.java

How to test

$body = @{
  customerId = "customer-demo-1"
  lines = @(@{ searchTerm = "wireless mouse"; quantity = 2 })
} | ConvertTo-Json -Depth 5

Invoke-RestMethod http://localhost:8090/api/orders -Method POST -ContentType "application/json" -Body $body

# Then list via admin
Invoke-RestMethod http://localhost:8090/api/admin/orders

UI Customer page → enter search term + qty → Submit → see order id. Admin page → order appears as Created.

Logs Watch delivery-service for Kafka consume of oms.orders.created.

3. Customer order with image upload

Upload file → intake stores file + publishes ImageUploaded → Kafka → image-analysis → publishes ImageMatchSuggested → UI confirms item → then same as pathway 2

Path

  1. POST /api/images multipart file
  2. Intake saves object + publishes oms.images.uploaded
  3. image-analysis consumes → stub VisionProvider → oms.images.match-suggested
  4. UI picks a candidate itemRef, then POST /api/orders with imageId/itemRef

Files

web-app/.../customer-order.component.ts (onImageSelected, confirmMatch) intake-service/.../IntakeController.java (POST /images) intake-service/.../IntakeApplicationService.java intake-service/.../storage/LocalObjectStorage.java image-analysis-service/.../ImageAnalysisService.java docs/event-wiring.md

How to test

# Upload a small JPEG/PNG
$form = @{ file = Get-Item ".\some-photo.jpg" }
Invoke-RestMethod http://localhost:8090/api/images -Method POST -Form $form

# Check image-analysis logs for ImageUploaded consume
# Then submit order with returned imageId (or use UI)

UI Customer page → choose file → wait for candidates → click one → Submit.

5. Bulk purchase → receive → allocate

Admin UI → gateway → admin-bff → allocation-service → when fully allocated → Kafka oms.orders.fully-allocated → delivery status → Allocated

Endpoints

  • POST /api/admin/bulk-purchases
  • POST /api/admin/bulk-lines/{id}/received
  • POST /api/admin/allocations

Files

web-app/.../admin.component.ts admin-bff-service/.../AdminBffService.java (proxies to :8084) allocation-service/.../api/AllocationController.java allocation-service/.../service/AllocationApplicationService.java delivery-service/.../DeliveryApplicationService.java (FULLY_ALLOCATED listener)

How to test

  1. Create an order first (pathway 2) and note orderId / order line id from admin detail.
  2. Record a bulk purchase for the same item / quantity.
  3. Mark bulk line received.
  4. Create allocation from bulk line → order line.
  5. When all lines full → order status becomes Allocated.
# Shape depends on AdminBffService body — use Admin UI forms if unsure
# After allocate, check:
Invoke-RestMethod http://localhost:8090/api/admin/orders/<ORDER_ID>

UI Prefer Admin page forms for bulk / receive / allocate (they send the correct JSON).

Shared plumbing: oms-eventing (after-commit Kafka publish, processed_event dedupe), topics in oms-eventing/.../Topics.java. Full table: docs/event-wiring.md. All services share one oms database.

How to test events

  • Do the HTTP action that produces the event.
  • Watch the consumer service log for the listener.
  • Confirm side effect (status change, notification log, image candidates).
  • Kafka must be up on localhost:9092 or listeners hang/fail.

Full E2E checklist (happy path)

  1. Health sweep — all ports UP + Kafka 9092.
  2. Catalog: homepage loads deals; optional scrape; some images appear.
  3. Order: submit text order → admin shows Created.
  4. Allocate: bulk → receive → allocate → status Allocated.
  5. Deliver: mark delivered → status Delivered_To_Customer.
  6. Notify: notification-service log shows send attempt.
  7. Track: homepage track with that order id works.
  8. Image path (optional): upload photo → candidates → confirm → submit.
Gateway route order matters: /api/orders (exact) goes to intake; /api/orders/** goes to order-service; /api/orders/*/delivered goes to delivery. Config: api-gateway/src/main/resources/application.yml.
