Order Management System

Requirements specification — drop-shipping fulfillment platform (EARS-format acceptance criteria)

Introduction

This document defines the requirements for a drop-shipping Order Management System (OMS). The system enables customers to submit orders through a website, allows administrators to record manual bulk purchases from external platforms, allocates received bulk-purchased units to individual customer order lines, and tracks the order lifecycle with dual delivery timing (platform-to-admin and admin-to-customer).

The MVP intentionally excludes WhatsApp-based intake and automated purchasing or external platform API integrations. These are deferred to a later release and listed under Out of Scope.

Requirement 1

Customer Order Intake

User Story: As a Customer, I want to submit an order for one or more items through the website, so that the Administrator can fulfill my request.
  1. WHEN a Customer submits an order containing at least one valid Customer_Order_Line, THE Intake_Service SHALL create exactly one Customer_Order associated with that Customer.
  2. WHERE a Customer_Order_Line specifies an item by search term, THE Intake_Service SHALL record the search term, which SHALL contain between 1 and 200 characters, for that Customer_Order_Line.
  3. WHERE a Customer_Order_Line specifies an item by image upload, THE Intake_Service SHALL record the uploaded image for that Customer_Order_Line.
  4. WHEN a Customer adds a Customer_Order_Line to a Customer_Order, THE Intake_Service SHALL record the requested quantity, which SHALL be an integer from 1 to 10,000, for that Customer_Order_Line.
  5. THE Intake_Service SHALL allow a single Customer_Order to contain from 1 to 100 Customer_Order_Lines.
  6. IF a Customer submits an order with no Customer_Order_Line, THEN THE Intake_Service SHALL reject the submission, persist no Customer_Order, and return a validation error indicating that at least one order line is required.
  7. IF a Customer_Order_Line specifies a quantity that is not an integer from 1 to 10,000, THEN THE Intake_Service SHALL reject the submission, persist no Customer_Order, and return a validation error indicating the invalid quantity and the affected order line.
  8. IF a Customer_Order_Line specifies neither a search term nor an uploaded image, THEN THE Intake_Service SHALL reject the submission, persist no Customer_Order, and return a validation error indicating that an item specification is required and the affected order line.
  9. IF a Customer_Order_Line specifies an uploaded image whose format is not JPEG or PNG, or whose size exceeds 10 MB, THEN THE Intake_Service SHALL reject the submission, persist no Customer_Order, and return a validation error indicating the invalid image and the affected order line.
  10. IF a Customer submits an order containing more than 100 Customer_Order_Lines, THEN THE Intake_Service SHALL reject the submission, persist no Customer_Order, and return a validation error indicating the maximum order line count was exceeded.
Requirement 2

Order Data Model

User Story: As an Administrator, I want each order to be tied to a single customer with its own line items, so that order ownership and contents are unambiguous.
  1. THE Order_Service SHALL associate each Customer_Order with exactly one Customer.
  2. THE Order_Service SHALL associate each Customer_Order_Line with exactly one Customer_Order.
  3. THE Order_Service SHALL record for each Customer_Order_Line an item reference and a requested quantity, where the requested quantity is an integer from 1 to 999,999.
  4. WHEN a Customer_Order is created, THE Order_Service SHALL assign to that Customer_Order an identifier that is unique across all Customer_Orders and that remains unchanged for the lifetime of the Customer_Order.
  5. IF a Customer_Order is submitted for creation without a reference to exactly one existing Customer, THEN THE Order_Service SHALL reject the creation, create no Customer_Order, and return an error indicating that a valid customer association is required.
  6. IF a Customer_Order_Line references an item that does not exist, THEN THE Order_Service SHALL reject the Customer_Order_Line, persist no part of the submitted order, and return an error indicating that the item reference is invalid.
  7. IF a Customer_Order_Line is submitted with a requested quantity that is not an integer or that falls outside the range 1 to 999,999, THEN THE Order_Service SHALL reject the Customer_Order_Line, persist no part of the submitted order, and return an error indicating that the requested quantity is out of range.
Requirement 3

Administrator Order Management

User Story: As an Administrator, I want to view and manage customer orders, so that I can process and fulfill them.
  1. WHEN an Administrator requests the order list, THE Admin_Console SHALL display every existing Customer_Order together with its unique identifier and current Order_Status.
  2. WHEN an Administrator requests the order list and no Customer_Order exists, THE Admin_Console SHALL display an empty order list without returning an error.
  3. WHEN an Administrator selects an existing Customer_Order, THE Admin_Console SHALL display the associated Customer, all Customer_Order_Lines of that Customer_Order, and the requested quantity of each Customer_Order_Line.
  4. IF an Administrator selects a Customer_Order that does not exist, THEN THE Admin_Console SHALL reject the request and return an error indicating that the Customer_Order was not found.
  5. WHEN an Administrator updates the Order_Status of a Customer_Order to a defined Order_Status value, THE Admin_Console SHALL persist the new Order_Status and retain it for subsequent retrievals of that Customer_Order.
  6. IF an Administrator attempts to update the Order_Status of a Customer_Order to a value that is not a defined Order_Status value, THEN THE Admin_Console SHALL reject the update, retain the previous Order_Status, and return a validation error indicating the Order_Status value is invalid.
Requirement 4

Bulk Purchase Recording

User Story: As an Administrator, I want to record manual bulk purchases made from external platforms, so that purchased stock can be tracked and allocated to customer orders.
  1. WHEN an Administrator records a Bulk_Purchase, THE Admin_Console SHALL store the External_Platform name, which SHALL contain between 1 and 100 characters, for that Bulk_Purchase.
  2. WHEN an Administrator records a Bulk_Purchase, THE Admin_Console SHALL store the Platform_Order_Placement_Date, which SHALL be on or before the current system date, for that Bulk_Purchase.
  3. WHEN an Administrator adds a Bulk_Purchase_Line, THE Admin_Console SHALL store the item reference, the purchased quantity, and the unit cost for that Bulk_Purchase_Line.
  4. THE Admin_Console SHALL allow a single Bulk_Purchase to contain from 1 to 500 Bulk_Purchase_Lines.
  5. IF an Administrator records a Bulk_Purchase without an External_Platform name or with a name outside 1 to 100 characters, THEN THE Admin_Console SHALL reject the record, persist no part of the Bulk_Purchase, and return a validation error identifying the External_Platform name as invalid.
  6. IF an Administrator records a Bulk_Purchase without a Platform_Order_Placement_Date or with a date after the current system date, THEN THE Admin_Console SHALL reject the record, persist no part of the Bulk_Purchase, and return a validation error identifying the Platform_Order_Placement_Date as invalid.
  7. IF a Bulk_Purchase_Line specifies a purchased quantity that is not an integer from 1 to 1,000,000, THEN THE Admin_Console SHALL reject the record, persist no part of the Bulk_Purchase, and return a validation error identifying the purchased quantity as invalid.
  8. IF a Bulk_Purchase_Line specifies a unit cost outside the range 0.01 to 999,999,999.99, THEN THE Admin_Console SHALL reject the record, persist no part of the Bulk_Purchase, and return a validation error identifying the unit cost as invalid.
  9. IF an Administrator records a Bulk_Purchase with no Bulk_Purchase_Line, THEN THE Admin_Console SHALL reject the record, persist no part of the Bulk_Purchase, and return a validation error indicating that at least one Bulk_Purchase_Line is required.
Requirement 5

Allocation of Bulk Units to Customer Orders

User Story: As an Administrator, I want to map received bulk-purchase units to individual customer order lines, so that each customer receives the correct items.
  1. WHEN an Administrator links a Customer_Order_Line to a Bulk_Purchase_Line with an allocated quantity that is an integer of at least 1, THE Allocation_Service SHALL create an Allocation that records the allocated quantity, the source Bulk_Purchase_Line, and the target Customer_Order_Line.
  2. WHEN an Administrator marks units of a Bulk_Purchase_Line as received with a received quantity that is an integer of at least 0, THE Allocation_Service SHALL record the received quantity for that Bulk_Purchase_Line.
  3. THE Allocation_Service SHALL track, for each Bulk_Purchase_Line, the total allocated quantity across all Allocations.
  4. THE Allocation_Service SHALL track, for each Customer_Order_Line, the total allocated quantity across all Allocations.
  5. IF an Administrator attempts to allocate a quantity from a Bulk_Purchase_Line that exceeds the received quantity minus the already-allocated quantity for that Bulk_Purchase_Line, THEN THE Allocation_Service SHALL reject the request without creating or modifying any Allocation, leave the Bulk_Purchase_Line allocated and received quantities unchanged, and return an error indicating that the requested quantity exceeds the available unallocated received quantity.
  6. IF an Administrator attempts to allocate a quantity to a Customer_Order_Line that exceeds the requested quantity minus the already-allocated quantity for that Customer_Order_Line, THEN THE Allocation_Service SHALL reject the request without creating or modifying any Allocation, leave the Customer_Order_Line allocated quantity unchanged, and return an error indicating that the requested quantity exceeds the remaining unallocated requested quantity.
  7. WHEN the total allocated quantity for a Customer_Order_Line equals the requested quantity of that Customer_Order_Line, THE Allocation_Service SHALL mark that Customer_Order_Line as fully allocated.
  8. IF an Administrator attempts to create an Allocation with an allocated quantity that is not an integer or is less than 1, THEN THE Allocation_Service SHALL reject the request without creating any Allocation and return an error indicating that the allocated quantity is invalid.
Requirement 6

Order Status Lifecycle

User Story: As an Administrator, I want each order to progress through defined status states, so that I can track fulfillment progress.
  1. THE Delivery_Tracker SHALL constrain the Order_Status of every Customer_Order to exactly one of the following defined states: Created, Allocated, and Delivered_To_Customer.
  2. WHEN a Customer_Order is created, THE Delivery_Tracker SHALL set the Order_Status to Created.
  3. WHEN all Customer_Order_Lines of a Customer_Order are fully allocated, THE Delivery_Tracker SHALL update the Order_Status to Allocated.
  4. WHEN an Administrator marks a Customer_Order as delivered to the Customer and the Order_Status of that Customer_Order is Allocated, THE Delivery_Tracker SHALL update the Order_Status to Delivered_To_Customer.
  5. IF an Administrator attempts to mark a Customer_Order as delivered to the Customer when the Order_Status of that Customer_Order is not Allocated, THEN THE Delivery_Tracker SHALL reject the action, leave the Order_Status unchanged, and return an error indicating the order is not in a state eligible for delivery.
  6. WHEN the Order_Status of a Customer_Order changes, THE Delivery_Tracker SHALL persist a transition record for that Customer_Order containing the prior Order_Status, the new Order_Status, and the timestamp of the transition.
  7. THE Delivery_Tracker SHALL retain every persisted Order_Status transition record for each Customer_Order for the lifetime of that Customer_Order.
Requirement 7

Dual Delivery Timing

User Story: As an Administrator, I want the system to compute delivery durations from the platform order placement date, so that I can measure fulfillment speed at each stage.
  1. WHEN an Administrator marks a Bulk_Purchase as delivered to the Administrator, THE Delivery_Tracker SHALL compute the Platform_To_Admin_Duration, expressed as a non-negative integer number of whole seconds, as the elapsed time from the Platform_Order_Placement_Date to the delivered-to-admin timestamp.
  2. WHEN an Administrator marks a Customer_Order as delivered to the Customer, THE Delivery_Tracker SHALL compute the Admin_To_Customer_Duration, expressed as a non-negative integer number of whole seconds, as the elapsed time from the Platform_Order_Placement_Date to the delivered-to-customer timestamp.
  3. THE Delivery_Tracker SHALL store the Platform_To_Admin_Duration for each Bulk_Purchase that has been marked delivered to the Administrator.
  4. THE Delivery_Tracker SHALL store the Admin_To_Customer_Duration for each Customer_Order that has been marked delivered to the Customer.
  5. IF an Administrator attempts to mark a Bulk_Purchase as delivered to the Administrator when the Bulk_Purchase has no Platform_Order_Placement_Date, THEN THE Delivery_Tracker SHALL reject the action, record no delivered-to-admin timestamp, and return an error indicating the placement date is missing.
  6. IF an Administrator attempts to mark a Customer_Order as delivered to the Customer when the associated Platform_Order_Placement_Date is unavailable, THEN THE Delivery_Tracker SHALL reject the action, record no delivered-to-customer timestamp, and return an error indicating the placement date is missing.
  7. IF the delivered timestamp precedes the Platform_Order_Placement_Date, THEN THE Delivery_Tracker SHALL reject the action and return an error indicating the delivered timestamp is invalid.
Requirement 8

Delivery Confirmation and Customer Notification

User Story: As an Administrator, I want to mark items delivered to me and notify the customer when their order is delivered, so that customers are kept informed.
  1. WHEN an Administrator marks a Bulk_Purchase as delivered to the Administrator, THE Delivery_Tracker SHALL record the delivered-to-admin timestamp for that Bulk_Purchase and set the Bulk_Purchase status to delivered-to-admin.
  2. IF an Administrator attempts to mark a Bulk_Purchase as delivered to the Administrator and that Bulk_Purchase already has a delivered-to-admin timestamp, THEN THE Delivery_Tracker SHALL reject the request, retain the existing timestamp, and return an error indicating that the Bulk_Purchase is already marked delivered.
  3. WHEN an Administrator marks a Customer_Order as delivered to the Customer, THE Delivery_Tracker SHALL record the delivered-to-customer timestamp for that Customer_Order and set the Order_Status to Delivered_To_Customer.
  4. IF an Administrator attempts to mark a Customer_Order as delivered to the Customer and that Customer_Order already has a delivered-to-customer timestamp, THEN THE Delivery_Tracker SHALL reject the request, retain the existing timestamp, and return an error indicating that the Customer_Order is already marked delivered.
  5. WHEN a Customer_Order is marked delivered to the Customer, THE Notification_Service SHALL send a delivery notification to the Customer associated with that Customer_Order within 60 seconds of the delivered-to-customer timestamp being recorded.
  6. IF the Notification_Service fails to send a delivery notification to the Customer, THEN THE Notification_Service SHALL retry delivery up to 3 times and, if all attempts fail, record the notification as failed and return an error indicating that the delivery notification could not be sent, while retaining the delivered-to-customer timestamp.

Out of Scope (Deferred to a Later Release)

WhatsApp channel — order intake, communication, or notification through WhatsApp. The MVP supports website intake only.
Automated purchasing and external platform API integrations — programmatic order placement on external platforms and any API-based integration. The MVP supports manual recording of bulk purchases only.
